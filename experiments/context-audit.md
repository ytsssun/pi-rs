# Native context policy audit

A real policy change now appends `context_policy_changes` with `after_messages`, `previous_tool_chars`, and `tool_chars` (null means full view). Anchors refer to the canonical message count at the change, not timestamps or provider call indices. Canonical messages remain untouched; repeated identical policy makes no duplicate entry. Changes made after follow-up insertion anchor to that new message count. Audit never enters provider messages.

Legacy v1 sessions without this field load with an empty audit; no fictional past changes are synthesized. First new change records the previously loaded policy. Validation checks bounds, ordering, connected previous/new transitions and latest-policy agreement. This is a logical append history within the existing atomically replaced snapshot. It is not tamper-proof, a separate durable event stream, a complete transcript-edit protocol or Pi session compatibility. Older binaries with deny_unknown_fields cannot read the new field; current binaries read older v1 sessions. Use the matching current runtime after upgrade.
